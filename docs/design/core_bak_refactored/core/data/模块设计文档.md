## 一、模块概述
**定位**: 核心数据子系统，提供历史/实时/基础面数据，支持多源回退与三级缓存。
**价值**: 稳定可靠的数据供给、清晰的责任边界、可测试的模块化实现。

---

## 二、分层架构
```
┌───────────────────────┐ 业务协调层（Coordinator）
│ DataFetcher           │ ← 统一入口、策略编排、性能指标
└───────────────────────┘
           ↓
┌───────────────────────┐ 业务服务层（Service）
│ Providers Facade      │ ← 多源适配器门面（Yahoo/AV/IEX/…）
│ Quality Metrics       │ ← 数据质量指标聚合（读取型）
│ Market Status         │ ← 市场状态/板块表现/广度/情绪
└───────────────────────┘
           ↓
┌───────────────────────┐ 技术支撑层（Infra）
│ Cache (TTL/LRU/Redis) │ ← 三级缓存 & 压缩序列化
│ HTTP Clients          │ ← aiohttp/requests 会话池
│ Credentials           │ ← 各源凭证/速率/认证类型
└───────────────────────┘
           ↓
┌───────────────────────┐ 数据模型层（Model）
│ MarketData/Enums      │ ← 数据结构 & 枚举
└───────────────────────┘
```

## 四、模块间依赖关系
- 输入：外部API（Yahoo/AV/IEX/Polygon…）、配置（凭证、速率、缓存）、依赖注入（custom_sources）
- 输出：标准化 [MarketData] 列表与监控指标；供应用层 [DataQualityAPIService]/[DataQualityDashboard] 调用

## 五、业务流程
### 5.1 历史数据获取
1) 入口参数校验 → 2) 生成缓存键 → 3) 读缓存（命中返回） → 4) 并发请求主源 → 5) 回退源按优先级补全 → 6) 写缓存 → 7) 更新性能指标 → 8) 返回结果

### 5.2 实时数据/流式
1) 选择实时源 → 2) 建立WS连接 → 3) 解析增量消息→ 4) 回调分发 → 5) 断线重连与回退策略

### 5.3 基础面与市场状态
- 基础面：多源聚合，缺失降级
- 市场状态：开闭市、板块表现、广度、情绪、质量指标合并

---

## 六、关键设计决策
- 组合优先的委托模式：入口只编排，计算/IO由各模块承担（Composition over Inheritance）
- 三级缓存：命中优先返回；Redis压缩序列化；缓存失败不影响主流程
- 速率与凭证：独立管理器统一读取与校验，避免散落在各Provider
- 可替换的数据源适配：统一 `fetch(...) -> List[MarketData] | None` 签名

---

## 七、测试策略
- 单元测试：各Provider解析、缓存读写、凭证读取、HTTP失败回退（≥90%覆盖）
- 集成测试：主/备回退矩阵（成功/失败/空返回）、多标的并发、性能指标更新
- 流式测试：断线重连、消息分发、回退实时源
