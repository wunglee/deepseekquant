# 数据模块（core/data）- 模块设计文档

## 文档元信息
- 文档版本: v1.0
- 创建日期: 2025-11-27
- 最后更新: 2025-11-27
- 适用范围: core_bak_refactored/core/data（不含子目录 _fragments）
- 设计原则: 面向接口编程（Protocol/抽象接口）、依赖注入（DI）；实现与测试严格隔离

## 1. 模块概述与职责

数据模块提供统一的数据获取、验证、质量评估与报告能力，为风险、组合、信号等上层模块提供可靠的数据基础。

核心职责：
1. 数据获取：多数据源历史/实时/宏观/基金/股票数据
2. 数据验证：完整性、时间一致性、范围合理性、交叉源一致性
3. 数据质量：质量指标计算、质量监控策略、质量报告与告警
4. 数据模型：统一的数据结构与质量描述

## 3. 模块依赖关系

- 对内依赖：
  - DataFetcher/StockDataFetcher/FundDataFetcher/MarketDataFetcher → MarketData
  - DataValidator/DataQualityMetrics → MarketData
  - DataQualityMonitor → DataQualityPolicy/QualityReport/QualityFlags
  - DataQualityReporter → DataQualityMetrics
  - PolicyConfigLoader → DataQualityPolicy
  - DataProcessor → DataFetcher/DataValidator/DataQualityMonitor

- 对外依赖（基础设施/第三方）：
  - HTTP客户端：aiohttp、requests
  - 缓存：内存TTL/LRU、Redis（可注入并可选）
  - 数据适配器：Tushare/AKShare/YFinance等（通过统一接口注入）
  - 科学计算：numpy、pandas、scipy（可选）
  - 告警通道：email/slack/sms/webhook（配置驱动）

- 隔离约定：临时系统中不强制依赖真实外部服务；所有外部依赖通过注入适配器与配置隔离。

## 4. 数据流与控制流（简述）

1) 历史数据获取：
- 输入：symbols/period/interval/data_type/adjustments
- 流程：缓存命中→主数据源→失败收集→备用源重试→合并结果→缓存写入→性能统计
- 输出：Dict[str, List[MarketData]]

2) 数据验证：
- 输入：List[MarketData]
- 流程：价格→成交量→时间→完整性→交叉源一致性→通过率统计→历史记录
- 输出：{valid, errors, warnings, passed_tests, total_tests, validation_time}

3) 质量监控：
- 输入：Dict 数据集 + DataQualityPolicy
- 流程：策略驱动检查（completeness 等）→标志位与原因→返回 QualityReport/QualityFlags
- 输出：(QualityReport, QualityFlags)

4) 质量报告：
- 输入：period
- 流程：窗口筛选→摘要→趋势→问题与建议→告警汇总→记录历史与统计
- 输出：Dict 报告结构

## 5. 设计原则与约束

- 接口/依赖注入：
  - 所有服务通过构造函数接收配置与依赖；支持注入替代实现（适配器、缓存、告警）。
  - DataProcessor 不直接构造默认实现，应支持注入自定义的 Fetcher/Validator/Monitor。

- 边界与隔离：
  - 仅使用 core_bak_refactored 内部代码与第三方库；禁止导入根目录未来系统代码。
  - 测试 Mock 仅存在于 tests/，生产实现不引用测试目录。

- 配置来源：
  - 质量策略严格来自专家配置（JSON）；禁止设定未确认的默认值。

## 6. 兼容性与迁移建议

- 将 data_processor.py 中对 _fragments 的依赖替换为正式 DataQualityMonitor（待后续迭代），以实现模块内自洽。
- 为 DataFetcher 引入统一的数据适配器接口（Protocol），由装配层注入具体实现（真实/Mock/加速版）。
- 对 Redis/HTTP 客户端实现提供工厂/接口，以便在临时系统中替换为本地内存/假实现。

## 7. 风险与注意事项

- 历史碎片代码可能存在未导入库/类型缺失/示例代码片段；本文档基于意图进行职责与依赖归纳。
- 质量算法（如统计检验/ML异常检测）需在后续迭代完善与验证；现阶段可保持接口不变。
- 告警通道与外部集成需在临时系统中做空实现或通过配置禁用。
