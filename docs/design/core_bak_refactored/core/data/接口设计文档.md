# 数据模块（core/data）- 接口设计文档

## 文档元信息
- 文档版本: v1.0
- 创建日期: 2025-11-27
- 最后更新: 2025-11-27
- 适用范围: core_bak_refactored/core/data（不含子目录 _fragments）
- 设计原则: 面向接口编程（Protocol/抽象接口）、依赖注入（DI）；实现与测试严格隔离

## 1. 接口分类与稳定性

| 接口类型 | 目标用户 | 示例 | 稳定性 |
|---------|---------|------|-------|
| 公开API | 上层业务模块 | DataProcessor.process() | ✅ 稳定 |
| 业务服务接口 | 模块内组件 | DataFetcher.get_historical_data() | ⚠️ 半稳定 |
| 数据模型 | 所有调用方 | MarketData, QualityReport | ✅ 稳定 |

说明：公开API保持签名稳定；服务接口可随实现优化调整但语义保持；数据模型稳定。

## 4. 公开API（协调器）

```python
# data_processor.py
class DataProcessor:
    def __init__(self, config: Dict[str, Any]): ...
    def process(self, data: Dict[str, Any]) -> Dict[str, Any]:
        """action: 'fetch' | 'validate' | 'monitor'"""
```

## 5. 依赖注入与装配约定（关键）
- 所有服务类（Fetcher/Validator/Monitor/Reporter）均通过构造函数接收配置与依赖，允许运行期注入替代实现（例如数据适配器、缓存、告警通道）。
- DataProcessor 应支持注入具体实现（例如 DataFetcher、DataValidator、DataQualityMonitor），避免在内部直接构造默认实现。
- 外部数据适配器（Tushare/AKShare/YFinance等）通过统一适配接口注入，不在生产代码中使用测试目录的 Mock。

## 6. 使用示例

```python
config = {
    'primary': 'yahoo',
    'fallback_sources': ['alpha_vantage'],
    'redis': {'enabled': False}
}
processor = DataProcessor(config)

# 获取历史数据
result = asyncio.run(processor.process({'action': 'fetch', 'symbols': ['AAPL'], 'period': '1y'}))

# 验证质量
validation = processor.process({'action': 'validate', 'data': market_data})

# 质量监控（基于策略）
policy = PolicyConfigLoader.load('config/data_quality_policy.json')
monitor = DataQualityMonitor(policy)
report, flags = monitor.validate({'prices': [...], 'returns': [...]})
```

## 7. 边界与注意事项
- 本模块为历史整理的逻辑碎片，部分实现可能不可直接运行；接口文档以“意图与边界”为准。
- 外部依赖（HTTP/Redis/第三方API）需通过注入与适配器隔离；在临时系统中不强制依赖真实服务。
- 严禁在实现代码中引入测试目录 Mock；测试模拟仅存在于 tests/。
