## 一、模块定位
**定位**: 应用层数据质量子系统，提供 REST 接口与可视化监控，依赖领域层质量监控能力。
**约束**: 不引入业务默认值，读取型服务为主；严格遵循“.职责单一”原则。

---

## 二、架构与拆分
```
┌────────────────────────────┐ API层（Flask REST）
│ Routing & Controllers      │ ← 端点路由+请求参数校验+调用质量监控
│ Exporter                   │ ← 导出质量/警报数据（JSON/CSV）
│ Config Management          │ ← 读取/更新应用配置（代理领域配置）
│ Health & Diagnostics       │ ← 健康检查/诊断报告/系统状态
└────────────────────────────┘
            ↓
┌────────────────────────────┐ Dashboard层（UI+WS）
│ Renderer (HTML/ECharts)    │ ← 仪表板模板渲染
│ Aggregator                 │ ← 汇总质量/性能/警报数据
│ WebSocket Manager          │ ← 订阅/取消订阅/广播更新
│ Update Worker              │ ← 后台周期刷新与广播
│ Config IO                  │ ← 仪表板配置导入/导出
└────────────────────────────┘
            ↓
┌────────────────────────────┐ 依赖（领域层读取）
│ DataQualityMonitor         │ ← 质量历史/警报/性能统计/导出接口
└────────────────────────────┘
```

## 三、组件清单（计划拆分文件）
| 组件 | 文件（计划） | 职责 | 依赖 |
|------|--------------|------|------|
| API Routing         | app/data_quality/api/routing.py         | 注册端点、参数校验、错误处理 | Controllers |
| API Controllers     | app/data_quality/api/controllers.py     | 质量/报告/警报/性能/指标/导出/配置 | Monitor/Exporter |
| API Exporter        | app/data_quality/api/exporter.py        | 质量与警报导出（JSON/CSV） | Monitor |

| Dashboard Renderer  | app/data_quality/dashboard/renderer.py  | HTML模板/ECharts初始化 | Aggregator |
| Dashboard Aggregator| app/data_quality/dashboard/aggregator.py | 汇总质量/性能/警报数据 | Monitor |

## 四、依赖关系
- 输入：领域层 [DataQualityMonitor] 的质量历史/警报/性能统计；应用层配置
- 输出：REST端点响应与WebSocket消息；HTML仪表板

---

## 五、流程说明
### 5.1 API请求
1) 路由匹配 → 2) 参数校验 → 3) 控制器调用 Monitor → 4) 聚合/过滤/分页 → 5) 返回 JSON/CSV

### 5.2 仪表板更新
1) 定时任务拉取质量/警报/性能 → 2) 聚合数据 → 3) 广播 WS 消息 → 4) 前端更新图表

---

## 六、设计决策
- API与Dashboard分别独立子包；控制器与渲染分离，防止职责混淆
- WebSocket管理与周期刷新分离，避免阻塞问题；广播失败容错与清理
- 导出器与配置管理独立，便于测试与替换

---

## 七、测试策略
- 单元测试：路由/参数校验/控制器出入参/分页过滤/导出格式/WS消息类型
- 集成测试：API端点响应矩阵、Dashboard端→后端数据流（Mock Monitor）

---

## 八、文档同步规范（CRITICAL）
- 新增端点/WS类型/控制器参数变更需同步本设计文档与接口文档；记录变更历史
- 与领域层契约（[DataQualityMonitor]）变更需双向同步
