## ❓ 咨询主题：迁移准入标准与边界澄清（非生产部署）

### 1) 迁移准入标准（`core_bak_refactored` → 根目录未来系统）
- 代码与测试：
  - 单元/集成测试通过率的最低要求（例如≥98%？）
  - 新增测试的覆盖维度（端到端、行业参数、跨市场一致性）是否已足够？
- 架构与文档：
  - 必需同步的设计文档清单（模块设计/接口设计/架构图）与更新粒度要求？
  - 接口契约稳定性判定标准（参数签名/返回结构/异常语义）？
- 版本与审计：
  - 迁移版本的标注方式（tag/semver）与审计字段（report_id/timestamp/metadata）要求？

### 2) 迁移路径与流程
- 迁移策略：是否建议“按模块分批迁移”（risk → data → backtest）还是“一次性整体迁移”？
- 依赖稳定性：迁移前需确保哪些依赖（数据源/汇率/市场配置）被标记为“稳定”？
- 文档/记录：是否需要在 `docs/consultation.md` 与各模块 `SPRINT.md` 中追加“迁移确认记录”？

### 3) 数据源与降级策略的接受口径
- 真实数据源：是否必须接入 JoinQuant/Wind/Tushare 等备源后再迁移？
- 降级策略：对 Yahoo 限流与中国指数不可用的降级（Mock）是否可作为迁移前的临时接受口径？需要增加哪些交叉验证？

### 4) UAT与报告（迁移前可生成的“评审版”）
- 在临时系统中是否需要生成“迁移评审版UAT报告”（非生产模板）？
- 报告的最低内容清单（历史回测摘要、跨市场一致性、行业参数统计、数据质量、性能指标）？

### 5) 行业参数与跨市场校准的最终阈值确认
- 行业差异阈值：是否坚持≥10%，或接受≥6%（考虑随机性）的过渡口径？是否建议扩大样本量或细分行业？
- 跨市场一致性：相关性≥0.85的口径是否需要增加市场权重或分层阈值？

### 6) 专家偏好与优先顺序
- 迁移偏好：渐进式 vs 一次性？
- 优先迁移模块列表：是否优先 risk/data/backtest，或根据依赖链排序？
