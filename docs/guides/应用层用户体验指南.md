## 概述

### 应用层架构

应用层 (`core_bak_refactored/app`) 是面向最终用户的服务层，提供：

```
core_bak_refactored/app/quality_monitoring/    # 数据质量监控场景
├── api_service.py                      # REST API 服务（53个端点）
├── dashboard.py                        # Web 可视化仪表板
├── monitoring_service.py       # 监控服务整合层
├── scheduler.py                # 定时任务调度器
├── app_example.py             # 应用启动示例
├── quality_monitor_adapter.py  # 适配器（兼容遗留接口）
├── api/                        # API 组件模块
│   ├── controllers.py          # 业务控制器
│   ├── system_metrics.py       # 系统指标收集
│   ├── system_status.py        # 系统状态管理
│   └── ...
├── dashboard_components/       # 仪表板组件
│   ├── aggregator.py           # 数据聚合器
│   ├── websocket_handler.py    # WebSocket 实时推送
│   └── chart_builder.py        # 图表生成器
└── templates/                  # Web 模板
    ├── dashboard.html          # 质量监控仪表板
    ├── data_explorer.html      # 数据浏览器
    ├── rules_manager.html      # 质量规则管理
    ├── scheduler_console.html  # 调度控制台
    ├── alerts_center.html      # 警报中心
    ├── providers_credentials.html  # 数据来源管理
    ├── validation_reports.html # 验证报告
    └── realtime_monitor.html   # 实时监控
```

### 核心特性

| 特性 | 描述 | 适用场景 |
|-----|------|---------|
| **REST API** | 53个完整端点，覆盖质量数据、报告、警报、性能、配置管理 | 系统集成、自动化脚本 |
| **Web 仪表板** | 实时可视化监控，支持 WebSocket 推送 | 人工监控、数据分析 |

| **数据导出** | JSON/CSV/HTML 多格式导出 | 数据存档、外部分析 |

## 快速开始

### 方式一：使用 main.py（推荐）

这是最简单的启动方式，支持命令行参数配置。

```bash
# 基本启动（默认端口 5001）
python -m core_bak_refactored.app.main

# 自定义端口
python -m core_bak_refactored.app.main --port 8080

# 指定调度策略和端口
python -m core_bak_refactored.app.main --strategy apscheduler --port 5001

# 自定义监听地址
python -m core_bak_refactored.app.main --host 127.0.0.1 --port 5001

# 查看帮助
python -m core_bak_refactored.app.main --help
```

**数据源配置**：

数据源类型通过配置文件 `config/dev/data.yml` 中的 `primary_source` 控制：

```yaml
# config/dev/data.yml
primary_source: mock  # 数据源类型: mock, yahoo, tushare
```

可选值：
- **`mock`**：使用模拟数据提供者（不调用外部API，适合开发和演示）
- **`yahoo`**：使用Yahoo Finance真实数据（可能遇到限流）
- **`tushare`**：使用Tushare数据源（需要配置API Token）

**命令行参数**：

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|--------|------|
| `--strategy` | str | `apscheduler` | 调度策略（thread/apscheduler/celery） |
| `--port` | int | `5001` | API 服务端口 |
| `--host` | str | `0.0.0.0` | API 服务监听地址 |

**访问地址**：
- REST API: `http://localhost:5001/api/v1/`
- Web 仪表板: `http://localhost:5001/dashboard`
- 数据浏览器: `http://localhost:5001/explorer`
- 质量规则: `http://localhost:5001/rules`
- 调度控制台: `http://localhost:5001/scheduler`
- 警报中心: `http://localhost:5001/alerts-center`
- 数据来源: `http://localhost:5001/providers`
- 验证报告: `http://localhost:5001/validation`
- 实时监控: `http://localhost:5001/realtime`
- 健康检查: `http://localhost:5001/api/v1/health`

**优雅停止**：按 `Ctrl+C` 或发送 SIGTERM 信号。

## 核心服务

### 1. QualityMonitoringService（监控服务）

**职责**：整合质量检查器和告警管理器，提供统一监控接口。

**使用示例**：

```python
from core_bak_refactored.app.data import QualityMonitoringService
from core_bak_refactored.core.monitoring.alert_manager import AlertConfig

# 初始化服务
service = QualityMonitoringService(
    alert_config=AlertConfig(wechat_webhook_url='...')
)

# 获取质量历史（最近24小时）
history = service.get_quality_history(hours=24)
print(f"质量记录数: {len(history)}")
for record in history:
    print(f"时间: {record['timestamp']}, 得分: {record['overall_score']:.2f}")

# 获取告警历史
alerts = service.get_alert_history(hours=24)
print(f"告警数: {len(alerts)}")

# 生成综合报告
report = service.generate_comprehensive_report(period='7d')
print(f"报告摘要: {report['summary']}")
```

**关键方法**：

| 方法 | 参数 | 返回值 | 描述 |
|-----|------|--------|------|
| `get_quality_history()` | `hours=24` | `List[Dict]` | 获取质量历史记录 |
| `get_alert_history()` | `hours=24, severity=None` | `List[Dict]` | 获取告警历史 |
| `generate_comprehensive_report()` | `period='7d'` | `Dict` | 生成综合报告 |
| `get_performance_stats()` | - | `Dict` | 获取性能统计 |
| `export_monitoring_data()` | `filepath, format='json'` | `bool` | 导出监控数据 |

---

### 2. MonitoringScheduler（调度器）

**职责**：定时执行质量检查任务，支持三种调度策略。

**使用示例**：

```python
from core_bak_refactored.app.data.scheduler import MonitoringScheduler

# 创建调度器（生产环境推荐 apscheduler）
scheduler = MonitoringScheduler(
    monitoring_service=service,
    strategy='apscheduler',
    check_interval=300  # 5分钟检查一次
)

# 启动调度
scheduler.start()

# 获取调度状态
status = scheduler.get_status()
print(f"调度器运行: {status['running']}, 下次运行: {status['next_run']}")

# 手动触发检查
scheduler.trigger_check()

# 停止调度
scheduler.stop()
```

**调度策略对比**：

| 策略 | 优点 | 缺点 | 适用场景 |
|-----|------|------|---------|
| `thread` | 简单、无依赖 | 单进程、不持久化 | 开发测试、小型部署 |
| `apscheduler` | 持久化、易配置 | 单机限制 | **生产环境（推荐）** |
| `celery` | 分布式、高可用 | 需要 Redis/RabbitMQ | 大规模分布式系统 |

### 3. DataQualityAPIService（REST API）

**职责**：提供53个 REST API 端点，支持系统集成和自动化。

**核心端点分类**：

#### 质量数据端点
- `GET /api/v1/quality/current` - 获取当前质量数据
- `GET /api/v1/quality/report` - 生成质量报告
- `GET /api/v1/quality/history` - 获取历史记录

#### 告警端点
- `GET /api/v1/alerts` - 获取告警历史（支持过滤分页）
- `POST /api/v1/alerts/test` - 测试告警通道

#### 性能端点
- `GET /api/v1/performance` - 获取性能统计
- `GET /api/v1/metrics` - 获取监控指标

#### 系统管理
- `GET /api/v1/health` - 健康检查
- `GET /api/v1/diagnostics` - 运行诊断
- `GET /api/v1/status` - 获取系统状态
- `POST /api/v1/maintenance` - 维护模式

#### 配置管理
- `GET /api/v1/config` - 获取配置
- `PUT /api/v1/config` - 更新配置

#### 数据导出
- `GET /api/v1/export` - 导出数据（支持 JSON/CSV）

### 5.1 Dashboard（质量监控仪表板）

**访问路径**：`http://localhost:5001/dashboard`

**功能场景**：提供数据质量监控的总览视图，实时展示质量得分、趋势分析、警报列表和系统状态。

#### 主要功能

**1. 实时质量监控**

**质量得分卡片**：
- 总体得分（Overall Score）
- 完整性（Completeness）
- 一致性（Consistency）
- 连续性（Continuity）
- 合理性（Reasonableness）

**视觉提示**：
- 🟢 绿色（>= 0.90）：优秀
- 🟡 黄色（0.70-0.89）：良好
- 🔴 红色（< 0.70）：需要关注

**2. 趋势图表**

**质量趋势图**（折线图）：
- X轴：时间（最近24小时）
- Y轴：质量得分（0-1.0）
- 多条线：各维度得分

**告警趋势图**（柱状图）：
- X轴：时间（按小时聚合）
- Y轴：告警数量
- 颜色：Critical（红）、Warning（黄）、Info（蓝）

**3. 告警面板**

**实时告警列表**：
- 最新告警滚动显示
- 严重性徽章（Critical/Warning/Info）
- 时间戳和消息内容
- 点击展开详情

**过滤器**：
- 按严重性过滤
- 按时间范围过滤
- 按数据源过滤

**4. 性能监控**

**系统资源**：
- CPU 使用率（百分比 + 趋势线）
- 内存使用（MB + 百分比）
- 磁盘 I/O（读/写速率）
- 网络流量（入/出带宽）

**服务性能**：
- API 响应时间（P50/P95/P99）
- 数据源延迟（各数据源对比）
- 缓存命中率（百分比）

**5. WebSocket 实时推送**

**自动更新内容**：
- 质量得分每5秒刷新
- 新告警立即弹窗通知
- 趋势图动态追加数据点

**连接状态指示器**：
- 🟢 已连接：实时数据流正常
- 🟡 重连中：网络波动，尝试重连
- 🔴 断开：无法接收实时更新

## 实时监控与告警

### 告警配置

配置文件：`core_bak_refactored/config/dev/alerting.yml`

```yaml
alerting:
  # 告警阈值
  thresholds:
    quality_score:
      critical: 0.70   # 低于此值触发 Critical
      warning: 0.85    # 低于此值触发 Warning
    
    data_completeness:
      critical: 0.80
      warning: 0.90
  
  # 通知渠道
  channels:
    wechat:
      enabled: true
      webhook_url: 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY'
      mention_users: ['@all']
    
    email:
      enabled: true
      smtp_server: 'smtp.example.com'
      smtp_port: 587
      sender: 'ops@example.com'
      recipients:
        - 'team@example.com'
        - 'oncall@example.com'
    
    webhook:
      enabled: false
      url: 'https://your-webhook.com/api/alerts'
  
  # 告警聚合（避免告警风暴）
  aggregation:
    enabled: true
    window_seconds: 300  # 5分钟窗口
    max_alerts: 10       # 窗口内最多发送10条
```

---

### 告警级别说明

| 级别 | 触发条件 | 通知方式 | 响应要求 |
|-----|---------|---------|---------|
| **Critical** | 质量得分 < 0.70<br>数据完整性 < 0.80<br>数据源全部失败 | 企业微信 + 邮件 + 电话 | **立即响应**（5分钟内） |
| **Warning** | 质量得分 0.70-0.85<br>数据完整性 0.80-0.90<br>主数据源失败 | 企业微信 + 邮件 | 30分钟内处理 |
| **Info** | 数据源切换<br>缓存未命中率高<br>性能指标波动 | 仅记录日志 | 跟踪观察 |

### 1. 端口清理脚本 (clean_port.sh)

**功能**：快速清理被占用的端口，解决启动时端口冲突问题。

**位置**：`scripts/clean_port.sh`

**使用方法**：

```bash
# 清理默认端口 5001
./scripts/clean_port.sh

# 清理指定端口
./scripts/clean_port.sh 8080

# 查看帮助
./scripts/clean_port.sh --help
```

**脚本特性**：

| 特性 | 说明 |
|-----|------|
| ✅ **智能检测** | 自动检测端口是否被占用 |
| 📋 **详细信息** | 显示占用进程的命令、PID、用户等信息 |
| ⚠️ **安全确认** | 终止进程前需要用户确认，防止误操作 |
| ✅ **结果验证** | 清理后自动验证端口是否释放 |
| 🔒 **错误处理** | 完善的错误提示和退出码 |

**使用场景**：

```bash
# 场景1：启动应用前清理旧进程
./scripts/clean_port.sh 5001
python -m core_bak_refactored.app.main

# 场景2：批量清理多个端口
for port in 5001 5002 5003; do
    ./scripts/clean_port.sh $port
done

# 场景3：集成到启动脚本
#!/bin/bash
./scripts/clean_port.sh 5001 <<< "y"  # 自动确认
python -m core_bak_refactored.app.main
```

**执行示例**：

```bash
$ ./scripts/clean_port.sh 5001

⚠️  是否要杀死这些进程？(y/N) y
🔨 正在终止进程...
✅ 端口 5001 已清理完成
```

**注意事项**：
- 👍 首次使用需要添加执行权限：`chmod +x scripts/clean_port.sh`
- ⚠️ 需要 `lsof` 命令支持（macOS 和 Linux 默认已安装）
- 🔒 建议每次启动应用前使用此脚本清理端口

## 故障排查

### 常见问题

#### 1. 端口被占用（常见）

**症状**：运行应用时报错：
```
Address already in use
```

- ✅ 验证清理结果

```python
from flask import request, jsonify
from functools import wraps
import jwt

def require_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        token = request.headers.get('Authorization', '').replace('Bearer ', '')
        try:
            jwt.decode(token, SECRET_KEY, algorithms=['HS256'])

        return f(*args, **kwargs)
```
